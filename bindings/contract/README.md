# Flare IM Bindings Contract

English · [中文](README.zh-CN.md)

**The single configuration directory**: for day-to-day binding extensions, edit
only the JSON in this directory, then run:

```bash
cargo xtask core-codegen
cargo xtask core-codegen-check
```

Rust `cargo xtask core-codegen` is the sole binding-generation entry point
(analogous to protoc), not a business-config source. When adding an API or
event, edit the JSON contract first; do not restore or add Python generation
scripts.

## Configuration files

| File | Purpose |
|------|---------|
| `manifest.json` | contract version, platform mapping, artifact paths |
| `apis.json` | canonical API id, C symbol, Tauri command name, core method |
| `dispatch.json` | JSON dispatch operation table (message / conversation / media / capability / message_build) |
| `direct_invoke.json` | `IMClient` direct-call routes (sync / presence / connection / diagnostics) |
| `c_typed_abi.json` | typed shim that preserves stable C symbols (argument parsing → `invoke_api_id_json`) |
| `client_config.json` | init / `SdkConfigOverlay` field docs and examples (incl. transport and protocol racing) |
| `generated/model_schemas/*.schema.json` | SDK wire model schemas generated from Rust DTO `JsonSchema` |
| `events.json` | event id, C code, `im://*` name, C JSON shape notes |
| `errors.json` | stable error codes |

## Init and transport configuration

Init uses the same JSON shape (camelCase) on all platforms:

- a bare [`SdkConfigOverlay`](../../src/client/lifecycle.rs) (the legacy C
  `flare_sdk_init` usage)
- or `{ "environment": "...", "sdkConfig": { ... } }` (recommended, consistent
  with `client.init` / `sdk.init`)

Key fields:

| Field | Description |
|------|-------------|
| `transportPolicy` | `auto` / `websocket_only` / `protocol_race` (the WASM runtime forces `websocket_only`) |
| `defaultTransport` | `websocket` / `quic`, preferred when not racing |
| `protocolRaceOrder` | e.g. `["quic","websocket"]`, race priority (earlier wins) |
| `wsUrl` / `quicUrl` | both must be configured when racing |

See `client_config.json` for examples; codegen emits
`CLIENT_INIT_REQUEST_EXAMPLE_JSON` and the per-platform `flare_client_*` /
`FLARE_SDK_CONFIG_EXAMPLE_JSON`.

Unified invoke: `client.init` → `sdk.init` (`direct_invoke.json`); Tauri still
keeps the `sdk_init` command passing through the same structure.

## Checklist for adding a capability

### JSON-style API (`sdk_invoke_json` / `flare_*_dispatch_json`)

1. Add the method to `apis.json` (`id`, `core`, `c`, `tauri`, etc.)
2. If it goes through dispatch: add the `op` definition under the matching
   `group.operations` in `dispatch.json`
3. `cargo xtask core-codegen`

Rust DTO schemas are generated by `cargo xtask schema` and their freshness is
checked by `cargo xtask schema-check`; do not hand-write
`generated/model_schemas/*.schema.json`.

### IMClient direct calls (sync / presence / connection state, etc.)

1. Add the method to `apis.json`
2. Add a `routes` entry in `direct_invoke.json` (the `route` matches the name
   after `operation.normalize`)
3. `cargo xtask core-codegen`

### Media upload/download (`flare_media_*`)

1. Add the method to `apis.json`
2. Path-style upload / delete file: add an `op` under `media.operations` in
   `dispatch.json` (may use `optional_upload_options`, `bytes_vec`)
3. Download to a user directory / synchronous cancel: add a `route` in
   `direct_invoke.json` (native uses `cfg: not(target_arch = "wasm32")`)
4. Stable C symbol: add an export in `c_typed_abi.json` (`upload_options` /
   `bytes_view` / `request_json` / `sync_bool_invoke`)
5. `cargo xtask core-codegen`

Other media controls (URL, cache, subdirectories, etc.) continue to go through
`flare_media_dispatch_json`.

### Stable C symbols (`flare_sdk_sync_*` / `flare_message_*`, etc.)

1. Add the method to `apis.json` (including the `c` symbol name)
2. Add an entry to `exports` in `c_typed_abi.json`: `symbol`, `api_id` (matching
   the apis id), `kind` (`invoke_unit` / `invoke_json` / `invoke_send_ack`),
   `args`
3. If the `api_id` is not yet implemented in `direct_invoke.json` or
   `dispatch.json`, add the corresponding route first
4. `cargo xtask core-codegen` → generates `c/src/generated/typed_abi.rs`

### Events

1. Add an entry to the `events` array in `events.json` (`id`, `cCode`,
   `cCodeName`, `tauri`, `cJson`)
2. Add the corresponding `SdkEvent` variant in the core (Rust remains the source
   of truth)
3. `cargo xtask core-codegen` — automatically generates:
   - `shared/.../event_registry.rs`
   - `tauri/.../event_emit.rs` (forwarding entry)
   - `wasm/.../events.rs`, `uniffi/.../events.rs` (contract tables)
4. If the payload shape is entirely new: add serialization in the currently
   enabled binding runtime / platform adapter; do not restore the old event
   bridge / Tauri `convert.rs` event chain.

## Platform crate responsibilities (keep them thin)

| Platform | Hand-maintained | Auto-generated |
|------|----------|----------|
| **c** | handles, memory, shared JSON runtime calls | `typed_abi`, `json_dispatch`, `invoke`, `events` |
| **tauri** | `sdk_init` / `sdk_invoke_json` IPC adapter | `handler`, `invoke`, `event_emit` |
| **wasm** | `FlareImClient` wasm-bindgen facade | `contract`, `bindings`, `events` |
| **uniffi** | later session adapter | `contract`, `types`, `events`, `invoke` placeholders |

## Unified call entry points

- **C**: `flare_sdk_invoke_json(api_id, params_json, …)` + generated legacy
  dispatch symbols
- **Tauri**: `sdk_invoke_json(api_id, request_json)` + `sdk_init` / `sdk_login`
  / `sdk_logout`
- **Wasm (smoke)**: `flareInvoke(runtime, api_id, request_json)`

The contract `api_id` matches the `id` field in `apis.json` (e.g. `message.list`,
`conversation.list`, `sync.conversation`).
